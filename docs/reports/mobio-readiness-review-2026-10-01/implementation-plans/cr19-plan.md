## Minimal coherent implementation after the freeze

1. **Bridge the installed plugin's scene callbacks.** Add a small `MobioSceneDelegate: FlutterSceneDelegate` in the already-compiled `ios/Runner/AppDelegate.swift` and reference `$(PRODUCT_MODULE_NAME).MobioSceneDelegate` from `Info.plist`. Import `app_links`; retain existing implicit-engine registration. Call the relevant superclass method exactly once for scene connection, open URL contexts, and continuing user activity. Forward cold connection `urlContexts` and browsing-web `userActivities`, warm URL contexts, and browsing-web continuation URLs to the installed `AppLinks.shared.handleLink(url:)`. Use one private forwarding helper rather than recursively calling scene overrides from the cold callback. Do not replace `FlutterSceneDelegate` with a plain UIKit delegate or remove scene adoption.

2. **Use one app-lifetime link subscription.** Add a small injected arrival coordinator at the app boundary, with one `AppLinks` stream subscription started before optional network/install-referrer work. The installed plugin stream includes the first captured link, so avoid each consumer separately reading/replaying `getInitialLink`. Buffer validated arrival while router/consumers attach, then drain in order. Maintain bounded duplicate suppression for repeated delivery of the same normalized intent within the existing short arrival window; permit a deliberate later open. Retain current Android native-reader callback handling separately. Route payment/NFC intents to the existing parsing/preview/composer workflow and referral intents to attribution; keep router replacement, Firebase readiness, and native NFC polling outside this coordinator.

3. **Make invite arrival deliberate.** Recognize canonical HTTPS `mobio.ikanisa.com/invite/<code>` and existing supported referral query aliases only on explicitly allowed Mobio entry paths; reject external hosts, credentials, explicit ports, fragments, extra invite path segments, empty/oversized values, and ambiguous duplicate parameters. Keep the server's code lookup authoritative. Recognize the existing custom NFC scheme through the existing NFC parser; it must not count as iOS universal-link install proof. Store the pending validated referral before choosing the existing Home/WhatsApp-login journey. Add an explicit `/invite/:code` route adapter for Flutter web/direct route restoration and any retained fallback; it must invoke the same coordinator/policy, with no referral RPC in a router redirect callback. Preserve the existing local redirect safety checks and verified WhatsApp requirement. A verified recipient goes to existing Home; signed-out/expired recipients finish the existing WhatsApp login journey and return to Home. No new reward screen or visual system is needed.

4. **Protect attribution ordering.** Let the provider own the single attribution instance and dispose its coordinator registration. Install-referrer capture remains an independent bounded source and cannot delay stream admission. Persist pending invite identity/revision together with code, source, and install proof; serialize pending writes. Only successful completion for the captured account and the exact still-current pending identity may clear it. Coalesce concurrent completion of the same pending identity/account. Do not automatically replay an unknown mutation outcome. Creating `iosul_` proof requires a validated HTTPS universal-link arrival, not merely an iOS stream source name. Store normalized attribution metadata needed by the existing contract rather than an arbitrary full incoming URL.

5. **Switch ownership only after replacement proof.** In the same completed batch, set iOS `FlutterDeepLinkingEnabled=false` and Android `flutter_deeplinking_enabled=false`. First prove native bridge delivery and Dart arrival routing for every declared link; do not land these flags alone. The web URL adapter remains active because browser routing is a different ingress. Run focused tests before the one combined parent-owned build/verification batch. No plugin upgrade, dependency resolution, entitlement expansion, or hosted mutation is required by this proposal.

Proposed write boundaries: `ios/Runner/AppDelegate.swift`, `ios/Runner/Info.plist`, `android/app/src/main/AndroidManifest.xml`; a new app-boundary coordinator/parser and its behavior tests; `lib/app/app.dart`, `lib/app/bootstrap.dart`, `lib/app/router/app_router.dart`, `lib/app/router/screen_wrappers.dart`; `lib/features/biopay/presentation/biopay_nfc_foreground_listener.dart`; `lib/features/profile/data/referral_attribution_service.dart`, `lib/features/profile/application/profile_services.dart`; the directly affected existing tests and `ios/RunnerTests/RunnerTests.swift`. Assign one owner per path before writes because this crosses frozen CR05/06 and root integration boundaries.

## Primary references checked

- [Installed plugin's versioned usage guide](https://pub.dev/packages/app_links/versions/6.4.1): instantiate early and use the stream for initial/further events; local cache source is the authority for the installed implementation.
- [Plugin maintainer's 6.x iOS integration guide](https://github.com/llfbandit/app_links/blob/main/doc/README_ios_6.md): public `handleLink(url:)` scene forwarding. The guide is live documentation, not proof that locked 6.4.1 registers scene callbacks.
- [Flutter UIScene migration guide](https://docs.flutter.dev/release/breaking-changes/uiscenedelegate): custom delegates retain Flutter scene lifecycle forwarding; scene-based plugins register their scene callbacks. Pinned 3.44 framework headers locally confirm `FlutterSceneDelegate`, `FlutterSceneLifeCycleDelegate`, and callback registration APIs.
- [Flutter default deep-link flag change](https://docs.flutter.dev/release/breaking-changes/deep-links-flag-change): plugin ownership requires explicitly disabling the default mobile handler. Apply this after complete replacement coverage, as required by CR19.
