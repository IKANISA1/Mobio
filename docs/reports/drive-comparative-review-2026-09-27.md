# Mobio Drive snapshot comparative review

27 September 2026. Reviewed against local and remote `main` at `aac2f5cb18286790b52d5ea38cd2b5e9c34f221f`.

## Decision

**NO-GO for an unrestricted production release.** The repository has a substantial Flutter, Supabase, Cloudflare and separate Android collector implementation. It is not a verified deployed service or accepted store build. The Drive assessment supplies a useful remediation register, but its 95 “Not started” rows describe that assessment's work program; they are not a finding that all 95 capabilities are absent. This review accepts, qualifies or defers each row below.

The most urgent external action is to contain the [shared Drive folder](https://drive.google.com/drive/folders/120JIOTyeNX6nHaHPDqS3UgbaTWyJAE57): connector metadata on 27 September showed an `anyone` `writer` permission, and the folder contains Android signing configuration and two keystores. I inspected names and permission metadata only, not credential values. This is exposure and source-integrity risk; it does not establish outsider use or a compromised production key. Limit access, preserve activity evidence, establish which certificate is actually active, and rotate or replace affected credentials based on that provenance. Do not import the shared `.git`, `.dart_tool`, `build`, signing files or generated output into the checkout.

## Most material corrections and additions

1. **Separate direct authority from UI visibility.** `bus_bookings` grants authenticated UPDATE (`supabase/migrations/20260608093000_public_transport_booking_foundation.sql:253`) and its owner-held policy does not protect status/payment/amount fields (`:401-413`). Prevent direct financial state writes before enabling or exposing that schema, then test actual PostgREST roles. The report is right about the source path, but its wording can imply an active ticketing UI that is not present.
2. **Fix identity at its source, including BioPay recipient resolution.** Login picks a mutable phone alias ordered by `created_at` (`verify-login-otp/index.ts:78-106`) and can update the selected Auth phone (`:183-206`); the profile RPC accepts `phone` (`20260614153000_rentals_vehicle_type_onboarding.sql:205-210`), and BioPay discovery uses `profiles.phone` (`20260908090000_biopay_payment_discovery.sql:239-245`). A verified, unique server-owned identity map is needed across both journeys. The Drive fixture is useful but is not proof of an actual account takeover.
3. **Close SMS auto-credit on trusted evidence.** The parser preserves amounts with `is_momo_payment=false` or low confidence (`supabase/functions/_shared/momo-sms.ts:166-199`). SQL can default the merchant to `12345` and match a lone invoice by amount/time without payer/member/reference (`20260906145000_subscription_receipt_integrity.sql:127-210`), then activate a subscription (`:253-285`). Require independent transaction evidence, explicit merchant/currency and unambiguous invoice binding; send uncertain receipts to review. The shared report did not execute a live false-credit transaction.
4. **Restore six-digit ID integrity.** `generate_numeric_member_id` hashes the UUID modulo 900,000 without collision handling (`20260324175000_comprehensive_rpcs.sql:39-72`). Client surfaces use fallback/hashes (`lib/features/profile/presentation/profile_screen.dart:69-104`). Add a unique allocator and controlled collision migration before treating a displayed code as a transfer or sharing authority.
5. **Treat the full visual suite as failed.** The historical 812 functional passes excluded the whole reference-golden suite (`docs/testing/face-ussd-implementation-20260920.md:80-109`). This review's full suite also failed on many golden comparisons. Review intended design changes and regressions individually; an image blanket update would erase acceptance evidence.
6. **Preserve the unresolved Storage service race omitted from the Drive register.** The existing full-system QA record still marks FQA-035 open after repeated private-object concurrent replacement tests (`docs/testing/fullstack-qa-20260914/findings.csv`, `remaining-tasks-20260919.md:84-87,232-234`). The Drive workbook has no FQA-035 row. Add an explicit service-version qualification and atomic create/replace authorization gate for any release that exposes private Storage uploads. This historical local reproduction is not evidence of a production incident.
7. **Correct documentation chronology.** `docs/release/go-no-go.md` describes BioPay/payment removal under an earlier scope, while `AGENTS.md:90-93`, the 8 September BioPay contract and 20 September face approval preserve later, narrower expansions. Add a dated current scope/status map and mark the old release page as historical; do not delete current approved features because that page says they were removed.
8. **Do not turn evidence gaps into unconditional feature work.** The workbook assigns P1 to disabled face, paid transport, SMS and collector items. These are gates for their affected feature, not reasons to invent a new route engine, in-app payment execution, liveness requirement, live payment status or a blanket whole-app blocker when those features are securely disabled. The core release still has its own identity, access, privacy, device, CI and QA gates.

Official current checks: [Google Play target API 36 for new app submissions and updates from 31 August 2026](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-gb), [Android 16 KB compatibility enforcement for updates from 1 February 2027](https://developer.android.com/guide/practices/page-sizes), [Apple's current Xcode 26/iOS 26 SDK minimum](https://developer.apple.com/news/upcoming-requirements/?id=04282026a), [Apple's in-app account-deletion initiation guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app), [GitHub's valid local reusable-workflow syntax](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows), [Cloudflare's Vectorize localization incompatibility](https://developers.cloudflare.com/data-localization/compatibility/), and [Supabase's backup scope excluding Storage objects](https://supabase.com/docs/guides/platform/backups). These are release-time checks, not proof of Mobio's live configuration or legal clearance.
