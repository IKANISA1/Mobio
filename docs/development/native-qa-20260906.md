## Country picker failure and correction

The actual iOS simulator app exposed a country-picker dismissal failure. Opening
the country sheet, searching for Rwanda, and selecting its row logged
`A TextEditingController was used after being disposed`, followed by framework
assertions and a red error screen. The subsequent app-link check revealed the
existing error screen; the log timestamps establish that country selection
triggered it before the link was opened.

The caller had disposed the search controller when the modal's result completed,
while its closing animation could still rebuild the text field. The picker now
stores only the search query and lets `TextField` own its controller for the full
mounted lifetime. Searching by name, ISO code, or dialing code is preserved.

The shared bottom-sheet content now has a transparent Material surface above its
background decoration. This also resolves the native `ListTile background color
or ink splashes may be invisible` diagnostics without changing the sheet colors,
shape, or layout.

Two additional login regression tests exercise search/selection, reopening with
a fresh query, and back dismissal while search remains focused. They use fake
login services and do not send messages.

The rebuilt iOS simulator app was then checked with Kenya selection, reopening,
and Rwanda selection. Both dismissals return to the login screen with the correct
code. The new app process logs zero Flutter errors for that recheck. An empty
`mobio://biopay/nfc` link leaves the signed-out app at login.
The rebuilt admin web page also passes search, selection, reopening with an empty
query, and focused-field dismissal, with no browser console warnings or errors.

## Android release smoke corrections

`scripts/release/smoke_android_release.sh` now rejects emulator evidence by
default, using the device serial and QEMU properties. Local QA can opt in with
`ANDROID_SMOKE_ALLOW_EMULATOR=true`; its log explicitly records
`device_type=emulator` and `physical_device_evidence=false`.
`go_no_go_check.sh` forces that opt-in off for its physical-device gate.

The smoke script also resolves Mobio's launcher activity and launches that exact
component with `am start -W`. The previous `monkey` invocation failed on this
emulator because of its physical-key event configuration. An unresolved launcher
fails the check instead of launching another activity.

QEMU properties, explicit emulator labeling, the default physical-device path,
unresolved activity rejection, and the production gate overriding an emulator
opt-in. The subprocess fixtures do not connect to devices or remote services.
